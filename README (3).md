# sbvm --- sing-box VMess + WebSocket 管理脚本

`sbvm` 是一个用于 Linux 服务器的 Bash 管理脚本，基于
[sing-box](https://github.com/SagerNet/sing-box)，提供 **VMess +
WebSocket、纯 IP（无域名）模式**下的节点创建与日常管理功能。

脚本以稳定性和便于维护为设计目标，包含配置校验、配置备份与回滚、systemd
服务管理、防火墙端口规则处理以及故障诊断等功能。

> **重要提示**
>
> -   当前脚本生成的节点配置为 **TLS 关闭**。VMess + WebSocket
>     不应被误认为是 HTTPS/TLS 连接，请根据实际网络环境评估安全风险。
> -   脚本需要以 `root`
>     身份运行，会修改系统配置、防火墙规则并安装服务。请先阅读脚本内容，并在你有管理权限的服务器上使用。
> -   云服务器的安全组、网络 ACL
>     等由服务商控制的规则，脚本无法代为修改；需要在服务商控制台另行放行对应
>     TCP 端口。
> -   本项目目前未在 README
>     中声明许可证。公开发布前，请根据你的授权意愿添加 `LICENSE` 文件。

## 功能特性

-   安装、重装、更新或切换 sing-box 版本。
-   创建、查看、修改和删除 VMess + WebSocket 节点。
-   自动生成 UUID、WebSocket 路径和可用候选端口。
-   导出 `vmess://` 分享链接；安装了 `qrencode` 时可在终端显示二维码。
-   输出可供其他 sing-box 或 Xray/V2Ray 前置机使用的出站配置片段。
-   通过 `systemd` 管理服务，并设置开机启动和故障后重启。
-   修改配置前先执行 sing-box
    配置检查；配置应用后若服务未能正常启动，会尝试恢复旧配置。
-   备份和恢复配置文件。
-   检查服务状态、监听端口、WebSocket 握手和本机防火墙状态。
-   尝试自动处理 `ufw`、`firewalld` 或 `iptables` 的 TCP 端口规则。
-   提供可选的网络参数调优功能（包括 BBR
    相关参数，实际效果取决于内核与系统环境）。
-   支持设置监听地址，以及手动指定分享链接中显示的公网 IP。

## 工作方式

脚本管理的主要文件和服务如下：

  项目                  路径或名称
  --------------------- ----------------------------------------
  sing-box 可执行文件   `/usr/local/bin/sing-box`
  管理命令              `/usr/local/bin/sbvm`
  主配置文件            `/etc/sing-box/config.json`
  脚本设置              `/etc/sing-box/sbvm.env`
  配置备份目录          `/etc/sing-box/backup/`
  sing-box 数据目录     `/var/lib/sing-box/`
  systemd 服务文件      `/etc/systemd/system/sing-box.service`
  服务名称              `sing-box`
  网络调优文件          `/etc/sysctl.d/99-sbvm.conf`

节点使用 VMess 协议和 WebSocket 传输，脚本生成的配置中 TLS
关闭。默认情况下，监听地址会根据系统 IPv6 环境选择 `::` 或
`0.0.0.0`；可在菜单的"脚本设置"中调整。

## 环境要求

-   Linux 服务器。
-   **需要 systemd 和
    `systemctl`**。虽然脚本会识别多种包管理器，但这不代表所有对应发行版都适用；没有
    systemd 的系统通常无法按此脚本的方式管理服务。
-   以 `root` 身份运行，或通过 `sudo` 执行。
-   服务器能够访问 GitHub Releases，以下载
    sing-box；首次运行时还可能需要下载或安装依赖。
-   常用依赖包括 `curl`、`tar`、`jq` 和提供 `ss` 命令的
    `iproute2`（部分发行版的软件包名称不同）。
-   `qrencode` 为可选依赖，仅用于在终端显示二维码。

脚本会识别以下 CPU
架构：`x86_64/amd64`、`aarch64/arm64`、`armv7`、`armv6`、`386`、`s390x`、`riscv64`。能否安装成功仍取决于
sing-box 对应版本是否提供匹配的官方发布包。

脚本尝试通过系统包管理器安装依赖，支持识别 `apt`、`dnf`、`yum`、`apk` 和
`pacman`。请优先选择带有 systemd、且依赖包可正常安装的 Linux 发行版。

## 安装与启动

### 1. 下载仓库

将下面的地址替换为你自己的 GitHub 用户名和仓库名：

``` bash
git clone https://github.com/<你的用户名>/<你的仓库名>.git
cd <你的仓库目录>
```

也可以在 GitHub 仓库页面下载 ZIP 压缩包并解压。

### 2. 执行脚本

``` bash
chmod +x sbvm.sh
sudo bash sbvm.sh
```

首次启动会检查依赖并显示管理菜单。选择
**`1) 安装 / 重装 sing-box`**，按提示选择版本：

-   直接回车：尝试获取最新稳定版本。
-   输入版本号：安装指定版本，可输入 `v` 前缀，也可不输入。

安装完成后，脚本会尝试将自身复制为
`/usr/local/bin/sbvm`。之后可以通过以下命令再次打开管理菜单：

``` bash
sudo sbvm
```

安装流程还会询问是否立即创建第一个节点。按提示操作即可。

> **版本获取说明：** 脚本先尝试通过 GitHub API 获取版本，再尝试解析
> GitHub Releases
> 的跳转地址；两种方式都失败时，会使用脚本内设置的备用版本号
> `1.11.0`。如果网络访问 GitHub
> 不稳定，请留意最终显示的目标版本，并在需要时手动指定版本。

## 菜单说明

  菜单   功能
  ------ --------------------------------
  `1`    安装 / 重装 sing-box
  `2`    新增节点
  `3`    删除节点
  `4`    修改节点
  `5`    查看节点、导出分享链接与二维码
  `6`    启动服务
  `7`    停止服务
  `8`    重启服务
  `9`    查看运行状态与监听端口
  `10`   查看实时日志
  `11`   更新或切换 sing-box 版本
  `12`   备份 / 恢复配置
  `13`   网络调优
  `14`   一键诊断自检
  `15`   设置监听地址 / 对外显示 IP
  `16`   彻底卸载
  `0`    退出菜单

## 创建节点后需要检查的项目

1.  在菜单中新增节点，并记录生成的端口、UUID、WebSocket 路径和分享链接。
2.  确认服务器本机防火墙已放行该节点的 **TCP 端口**。
3.  如果服务器使用云厂商安全组或网络 ACL，在服务商控制台放行相同端口。
4.  在客户端导入 `vmess://` 分享链接，并确认客户端支持相应的 VMess +
    WebSocket 配置。
5.  如果连接失败，优先运行菜单 `14`，再查看菜单 `9` 的状态和菜单 `10`
    的服务日志。

### NAT 或中转场景

如果服务器的实际公网入口 IP 与脚本自动探测到的 IP 不一致，可以进入菜单
`15`，选择手动指定对外显示的
IP。该设置用于生成节点分享信息，并不会自动配置 NAT、路由或中转规则。

### 监听地址

菜单 `15` 可设置监听地址：

-   `::`：尝试使用 IPv6 通配监听；具体双栈行为取决于系统网络配置。
-   `0.0.0.0`：监听 IPv4 通配地址。

修改监听地址后，设置主要用于新建节点。请结合服务器网络环境确认节点是否实际监听在预期地址上。

## 配置备份与回滚

-   修改配置时，脚本会先使用 sing-box 检查临时配置。
-   检查失败时，本次修改会被放弃。
-   配置应用后如果服务未正常启动，脚本会尝试恢复之前的配置并重启服务。
-   菜单 `12` 可手动备份当前配置或从已有备份恢复。
-   自动配置备份位于
    `/etc/sing-box/backup/`。脚本会清理旧的配置备份，因此重要配置仍建议另行下载保存。

这些回滚措施不能替代独立备份。进行大规模修改或升级前，建议先保存
`/etc/sing-box/` 中需要保留的配置。

## 诊断与常见问题

### 客户端无法连接

建议按顺序检查：

1.  运行菜单 `14`，查看服务、配置、端口、WebSocket
    握手和本机防火墙检查结果。

2.  运行菜单 `9`，确认服务处于运行状态且目标端口正在监听。

3.  运行菜单 `10` 查看实时日志，或使用：

    ``` bash
    sudo journalctl -u sing-box -n 100 --no-pager
    ```

4.  检查服务器本机防火墙规则。

5.  检查云服务器安全组、网络 ACL、上游防火墙及端口映射。

6.  核对客户端的服务器 IP、端口、UUID、传输方式和 WebSocket 路径。

如果本机检查通过但外部仍无法连接，云厂商安全组或上游网络规则是需要重点检查的项目。

### 安装或更新失败

-   检查服务器能否访问 GitHub Releases。
-   确认当前 CPU 架构有对应的 sing-box 发布包。
-   检查磁盘空间、系统时间和依赖安装情况。
-   如果自动获取版本失败，留意脚本是否采用备用版本
    `1.11.0`；必要时在安装或更新菜单中指定版本。

### 服务启动失败

查看日志：

``` bash
sudo systemctl status sing-box --no-pager -l
sudo journalctl -u sing-box -n 100 --no-pager
```

也可以运行菜单 `14` 检查配置文件和监听端口。

## 网络调优

菜单 `13` 会写入 `/etc/sysctl.d/99-sbvm.conf`
并尝试应用系统网络参数。不同内核、虚拟化环境和服务商的支持情况可能不同，调优不保证一定提升速度。

如果准备使用此功能，请先检查该路径是否已经存在文件，并自行备份重要的系统参数配置。不要在不了解影响的情况下直接覆盖已有调优设置。

## 卸载

在菜单中选择 `16) 彻底卸载`，并按提示输入大写 `YES` 确认。

卸载会停止并禁用服务，删除 systemd 服务文件、sing-box
二进制文件、脚本配置目录和数据目录，并移除脚本创建的网络调优文件。卸载前可以选择将
`/etc/sing-box/` 备份到 `/root/sbvm-backup/`。

> 卸载会删除节点配置和相关数据。请在确认不再需要这些内容后再执行；如需保留，请提前备份。
